# 部署与日常使用

Mermaid Studio 是纯前端应用，**没有后端**。部署 = 构建产物 + 一个本地静态服务，固定跑在
**http://127.0.0.1:5273/**，并**默认绑定 `0.0.0.0`**（同网段的手机/平板/同事也能打开）。

---

## 一、日常怎么用

| 想做什么 | 怎么做 |
| --- | --- |
| 开始用 | 双击 **`启动 Mermaid Studio.command`**（会自动起服务并打开浏览器） |
| 停止 | 双击 **`停止 Mermaid Studio.command`** |
| 更新到最新代码 | 双击 **`更新并重启.command`**（类型检查 → 回归 → 构建 → 重启） |
| 平时访问 | 浏览器收藏 **http://127.0.0.1:5273/**（服务在跑就能用） |
| 局域网访问 | 默认就开。启动窗口里那行 **`· 局域网访问：http://<本机IP>:5273/`** 直接发给对方 |

`.command` 双击会弹一个终端窗口，**关掉窗口不影响服务**；要停服务请用「停止」脚本。

> 服务不会开机自启（按你的选择）。重启电脑后，用之前再双击一次「启动」即可。

## 补充：皮肤与渲染引擎

顶栏 **🎨** 按钮在「暖色（默认，陶土橙）/ 冷色」之间切换，配合 🌙 月相按钮切换深浅色（4 种组合）。
皮肤只影响界面外壳与预览/导出主题，图表里节点的语义色不变。


预览 / SVG / PNG 默认用 **pele**（零依赖、同步、快、SVG 小），pele 出错会自动回退官方 mermaid.js 12。
两者都是前端本地渲染，不需要联网。想强制用官方 mermaid.js：检查器「图表设置 → 渲染引擎」切一下即可。

## 二、数据放在哪（重要）

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 所有图表 + 自定义节点块 | **浏览器 localStorage** | 绑定地址 `http://127.0.0.1:5273`，**换端口/换浏览器就看不到** |
| 备份包 | 你指定的目录（`.json`） | 「保存」面板 →「导出全部图表（备份）」 |
| md / mmd / 工程 json | 你指定的目录 | 「保存…」弹框里选位置，可开自动保存 |

**三条保命习惯**：

1. 每隔一段时间点一次 **保存 → 导出全部图表（备份）**，扔进固定目录（例如 `~/Documents/流程图/`）。
2. 在「保存…」弹框里选一个**固定文件**（如 `~/Documents/流程图/主流程.md`）并打开自动保存 —— 磁盘上永远有一份可读的 md。
3. **不要改访问地址**（端口 5273 / `127.0.0.1`）。如果换了地址，旧图不会自动出现，用备份包恢复即可。

> 换电脑 / 清缓存 / 换浏览器后的恢复方式：打开应用 →「保存」面板 →「从备份恢复」→ 选备份包。
> 重的图表会作为新的一份导入，不会覆盖现有数据。

## 三、目录结构

```
mermaid-studio/
├── 启动 Mermaid Studio.command   # 双击启动（默认局域网可访问）
├── 启动（局域网可访问）.command  # 旧入口，保留兼容（等同于「启动」）
├── 停止 Mermaid Studio.command   # 双击停止
├── 更新并重启.command            # 改完代码一键更新
├── dist/                         # 构建产物（静态服务就服务这里）
├── src/                          # 源码
├── scripts/
│   ├── serve.mjs                 # 零依赖静态服务（node:http）
│   ├── start.sh / stop.sh        # 启动、停止
│   ├── deploy.sh                 # typecheck → e2e → build → restart
│   ├── run-e2e.sh                # 端到端回归（需要 dev server）
│   ├── e2e-*.mjs                 # 315 项断言（17 组）
│   └── check-build.mjs           # 构建产物验收（不需要 dev server）
├── tests 与文档 docs/DEPLOY.md   # 本文件
└── .run/                         # 运行时目录（pid / 日志，可随时删）
```

## 四、手动命令（不想用脚本时）

```bash
cd ~/dev/mermaid-studio

npm run build                      # 构建
node scripts/serve.mjs             # 起服务（默认 0.0.0.0:5273，Ctrl+C 停止）
node scripts/serve.mjs --host 127.0.0.1   # 只给本机用
node scripts/serve.mjs --port 5280 # 换端口（注意：数据是跟着端口走的）

npm run dev                        # 开发模式，跑在 5274（不碰 5273 的正式数据）
npm run typecheck                  # 类型检查
MS_BASE=http://127.0.0.1:5274 bash scripts/run-e2e.sh   # 跑回归
node scripts/check-build.mjs http://127.0.0.1:5273      # 验收构建产物
```

## 五、升级流程

1. 改 `src/` 下的代码（或拉取新版本覆盖源码）。
2. 双击 **`更新并重启.command`**，它会依次：
   - `npm run typecheck`
   - 若 dev server（5274）在跑，则跑完整回归；否则跳过
   - `npm run build`
   - 重启静态服务
3. 浏览器刷新即可（`index.html` 不缓存，静态资源带 hash 自动更新）。

回滚：把上一次的 `dist/` 或源码目录备份覆盖回来，再执行一次「更新并重启」。

## 五点半、局域网访问（默认开启）

启动脚本**默认绑 `0.0.0.0`**：本机用 `http://127.0.0.1:5273/`，同网段设备用启动窗口打印的：

```
· 局域网访问：http://192.168.110.216:5273/
```

把这个地址给对方即可（本机 IP 变了就重新看一下这行）。

- 启动时**浏览器仍然打开 `127.0.0.1:5273`**，这样你已有的本地图表（数据按 origin 存）不会丢。
- 想恢复成只有本机能用：`MS_HOST=127.0.0.1 bash scripts/start.sh`（或双击「停止」后再这样启动）。
- 开发服务器（`npm run dev`，5274）同样默认绑 `0.0.0.0`，手机可以直接连 5274 调试。

注意事项：

- **每个人的图表数据都在自己的浏览器里**。别人打开这个地址，看到的是空白编辑器（带示例图），
  **看不到你的图**。要给别人看某张图，发文件更靠谱：
  - `.md`（含 mermaid 代码块）/ `.mmd` → 对方用「语法」面板导入；
  - 工程 `.json`（含自定义节点块）→ 对方用「保存 → 导入工程」；
  - 全量备份 `.json` → 对方用「保存 → 从备份恢复」。
- macOS 首次会弹「允许 node 接受传入连接吗？」→ 点**允许**。如果之前点过拒绝，去
  **系统设置 → 网络 → 防火墙 → 选项**里放行 `node`。
- 这台机的 IP 是路由器动态分配的，重启路由器可能变化；想固定就在路由器里做 DHCP 保留 / 静态分配。
- 没有任何登录鉴权——同网段任何人都能打开这个编辑器（但读不到你的本地数据）。

## 六、常见问题

**1. 双击 `dist/index.html` 打开是白屏？**
正常现象。构建产物是 ES module，还用到「另存为」文件 API，`file://` 下不能用。必须通过 http 访问（用启动脚本）。

**2. 启动脚本报「端口 5273 已被占用」？**
多半是 dev server 或上一次的静态服务还在跑：
```bash
bash scripts/stop.sh                       # 停静态服务
lsof -nP -iTCP:5273 -sTCP:LISTEN           # 看看是谁占着
```
开发时请用 `npm run dev`（5274），不要占用 5273。

**3. 页面打不开 / 一片空白？**
```bash
tail -50 .run/server-5273.log              # 看服务日志
curl -I http://127.0.0.1:5273/             # 服务在不在
```

**4. 图表不见了？**
先确认地址还是 `http://127.0.0.1:5273/`（数据按地址隔离）。确认无误后用「从备份恢复」导入备份包。

**5. 「选择位置并保存」没弹窗？**
只有 Chrome / Edge 支持 File System Access API。其它浏览器会退回普通下载（可在浏览器设置里打开「下载前询问每个文件的保存位置」）。

**6. 局域网打不开？**
默认已经绑 `0.0.0.0`，先确认：`lsof -nP -iTCP:5273 -sTCP:LISTEN` 应显示 `*:5273`；若显示 `127.0.0.1:5273`，说明用了 `MS_HOST=127.0.0.1` 启动。其余按顺序查：① macOS 防火墙是否放行 node；② 双方是否在同一网段（有些公司 Wi-Fi 开了「AP 隔离」）；③ 对方用的是不是你当前那台机的 IP（IP 变了看启动窗口）。

**7. 之前导出的文件怎么打开？**
- `.md` / `.mmd`：右侧「语法」标签 → **导入 .md / .mmd** → 选文件（`.md` 会自动抽 mermaid 代码块，并用 frontmatter 的 title 命名）
- 工程 `.json`：右侧「保存」标签 → **导入工程 .json**
- 全量备份 `.json`：右侧「保存」标签 → **从备份恢复**
- `.svg` / `.png`：双击用浏览器/预览打开，只是图片不能编辑

**8. 想换端口？**
把 `MS_PORT` 传进去即可，但**数据不会跟着走**：换端口 = 新 origin = 空数据。做法：先在旧地址导出备份，换端口后再导入。

**7. node_modules 能不能删？**
能，但要重新 `npm install`（约 1.8G）。`dist/` 也可以删，下次启动会重新构建。

## 七、部署前的验收清单

```bash
cd ~/dev/mermaid-studio
npm run typecheck                  # 类型检查
npm run build                      # 构建
MS_NO_OPEN=1 bash scripts/start.sh # 起服务
node scripts/check-build.mjs       # 构建产物验收（9 项）
```

全绿即可放心使用。开发回归（需要另开 `npm run dev`）：

```bash
MS_BASE=http://127.0.0.1:5274 bash scripts/run-e2e.sh   # 213 项
```
