# 关系图谱：可行性评估与实施方案

> 结论先说：**值得做，但要收窄成"只读·焦点邻域"这一件事**。增量约 850 行产品代码 + 一组 e2e，3 天量级。最大的成本不是力导向，而是"第二套交互模型"——这一点已经被"复用 React Flow"消掉了。

## 1. 已经拍定的决策

| # | 决策 | 取值 |
| --- | --- | --- |
| D1 | 主任务 | **从焦点节点看依赖邻域**；全局总览靠"缩小视角"顺带得到；不做汇报呈现 |
| D2 | 可编辑性 | **只读**。点选同步检查器，双击回流程图定位，不能改结构 |
| D3 | 坐标归属 | 布局坐标**只活在组件里**，绝不写回 `doc.nodes[].position` |
| D4 | 视觉过滤归属 | 聚焦压暗是纯视觉，**不得借用 `hidden`**（`hidden` 会进图层和文档） |
| D5 | 开关位置 | 顶栏分段控件；模式记在全局 `settings`，**不进 `.mermaid.json`** |
| D6 | 规模 | 按 ≤120 节点 / ≤250 边设计与验收 |
| D7 | 方向 | 连线按作者画的方向画箭头（`data.endMarker`，默认 `arrow`），**不推断外键方向** |
| D8 | 节点画法 | 圆点 + 表名 + 字段数徽标；焦点节点与被手动展开的节点渲染成表卡片 |
| D9 | 布局 | 手写力导向：BFS 跳数环初值 + 焦点 pin 中心 + 收敛后一次性渲染，零新依赖 |
| D10 | 载体 | 复用 React Flow：新增 `dot` 节点类型 + `graph` 连线类型 |
| D11 | 聚焦操作 | 单击聚焦（1 跳亮、其余压暗）+ 跳数档位 1/2/全部 + 点空白还原 |
| D12 | 诊断语义 | 继承既有图语言：虚线 = 待确认项（可筛"只看待确认"）、不合规标签连线标 ⚠ |
| D13 | 分组与可见性 | 不画分组框，同 `groupId` 同底色；`hidden` 一致不画；纯文本节点默认不画 |
| D14 | 命名 | 视图 =「关系图谱」，聚焦态 =「焦点邻域」，距离 =「跳」 |

## 2. 为什么不是"把 dagre 换成力导向"

现成的 `autoLayout` 就是 dagre（[layout.ts:111](../src/lib/layout.ts#L111)），它的输出是**分层有向图**——所有节点同等显眼，看不出"我离这张表有多远"。

真正让人发现问题的不是布局算法，而是**压暗**：焦点之外降到 15% 不透明度后，1 跳邻居自己浮出来，2 跳再补上一圈。这件事 dagre 表达不了，力导向本身也不表达；力导向只负责让**同一圈的邻居按亲疏自己抱团**，而不是按 dagre 的格子排队。所以力导向是"手感"，压暗才是"功能"。评估时别把预算花错地方。

## 3. 方案对比

| 方案 | 手感 | 成本 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A. React Flow + 手写力导向** | Obsidian 同级 | 中 | 需要两个新节点/边类型 | **选它** |
| B. 自建 SVG 画布 | 可控但需打磨 | 中高 | 平移/缩放/命中/选中/主题全部重写（约 200 行易错代码），且与画布的交互手感会分叉 | 否 |
| C. 引入 `d3-force` | 最好 | 低 | 多一个运行时依赖；本仓库"能自己写就不加" | 备选 |
| D. 纯 BFS 同心环（不跑力） | 确定性最好 | 低 | 跨环连线挤成一圈，看不出簇 | 否 |

选 A 的决定性理由：`getRfInstance().fitView` 被顶栏「适应视图」和左栏拖入定位依赖（[rf.ts](../src/lib/rf.ts)、[Toolbar.tsx:81](../src/components/Toolbar.tsx#L81)、[Palette.tsx:40](../src/components/Palette.tsx#L40)）。复用 React Flow，这两个功能在图谱模式下**零改动**继续工作；自建画布则要维护两套视口语义。

C 与 A 不冲突：真跑起来手感不够，再把 100 行手写模拟换成 `d3-force`，接口不变。这是一个可以**事后低成本升级**的决定，所以现在不抢先加依赖。

## 4. 数据从哪来（派生模型，不改文档）

输入只有 `doc.nodes` / `doc.edges`，派生规则：

- **排除** `data.isSubgraph` 的节点（分组框是流程图的排版概念）；
- **排除** `hidden` 的节点与边（与图层开关一致）；
- **纯文本节点**（`shape === 'text'`，是注释不是实体）默认不画，除非它有连线；
- **保留** `groupId` 作为同色线索，不画框；
- **边不聚合**：同一对表之间的多条连线全部保留（它们通常是不同字段的关系，合并会丢信息）。

派生结果是一个纯函数输出，不写回文档：

```ts
interface GraphModel {
  nodes: { id, label, fieldCount, groupId, expanded }[]
  edges: { id, source, target, dashed, warn, label }[]
  neighbors: Map<nodeId, nodeId[]>   // 1 跳邻接表
  hops: Map<nodeId, number>          // 到焦点的最短跳数（无焦点的全局距离）
  isolated: nodeId[]                 // 度数为 0，天然可见，不额外标记
}
```

`dashed` 直接读 `data.lineStyle === 'dashed'`（既有约定：虚线 = 待确认项，见 [exporters.ts:56](../src/lib/exporters.ts#L56)）；`warn` 用现成的 `isEdgeLabelConforming()`（[edgeLabels.ts:87](../src/lib/edgeLabels.ts#L87)）。

## 5. 布局：可复现的手写力导向

1. **初值**：从焦点出发 BFS，跳数即环序，环上均分角度；无焦点时按全图 BFS（取度数最大的节点当根）。固定随机种子做微小抖动，打散对称。
2. **力**：连边弹簧（目标长度按环差，跨环更短）+ 斥力（O(n²)，120 节点每 tick 7,200 对，可忽略）+ 最小间距碰撞。
3. **焦点 pin 在原点**，其余节点只在焦点半径外活动。
4. **收敛后一次性渲染**（约 300 tick，< 50ms），不做逐帧动画——否则每帧一次 React 重渲染，手感没赚到先亏性能。切模式时给一个短暂 CSS 过渡代替动画。
5. **「重排」按钮**：重新播种 + 重跑，用于打散意外重叠。
6. **缓存**：以"结构签名"（节点 id 列表 + 边端点列表）为缓存键。拖动画布节点只改 `position`，不触发重算；增删连线才重算。

为什么同步跑到位而不是动画：Obsidian 的动画是为了"探索感"，我们的场景是"看一眼依赖"。同步计算同时换来**可断言性**——e2e 能直接读最终坐标，而不是等动画结束。

## 6. 交互

| 操作 | 行为 |
| --- | --- |
| 单击节点 | 设为焦点：1 跳亮、其余压暗 15%；写 `selectOnly([id])` 让检查器跟上 |
| 跳数 1 / 2 / 全部 | 键盘 `1` / `2` / `0` + 画布角落小控件；改变高亮范围 |
| 点击空白 | 取消焦点，全部恢复 |
| 双击节点 | 切回流程图 + `selectOnly([id], true)` 定位该表 |
| 展开节点 | 节点右上角 `＋`：该点渲染成表卡片（字段可见），布局按卡片尺寸重跑 |
| 悬停边 | 显示 `类型: 说明` 浮层（字段锚定的提示位） |
| 滚轮 / 拖拽空白 | 缩放 / 平移（React Flow 原生） |

只读的边界很清楚：图上任何操作都不调用 `commit()`，因此不进撤销栈、不标 dirty。`selectOnly` / `selectEdge` 走的是裸 `set()`（[store.ts:843-873](../src/store.ts#L843-L873)），本来就不碰历史，正好可用。

## 8. 风险清单

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| **RF 单实例假设** | `getRfInstance()` 只存一个实例；两个画布同时挂载会互相抢 | `App` 里条件渲染，卸载流程图后再挂图谱；图谱也在 `onInit` 里 `setRfInstance` |
| **坐标被动写回** | React Flow 的 `onNodesChange` 会把位置变更写进 doc 并标 dirty（[store.ts:413-432](../src/store.ts#L413-L432)） | 图谱画布**不接** `onNodesChange`，`nodesDraggable={false}`；坐标只存在组件状态 |
| **`selected` 随文档落盘** | 选中是文档数据，点一次就会在下次保存时写盘（既有行为） | 接受（不标 dirty、不进历史）；图谱不得调用 `commit()` |
| **聚焦误用 `hidden`** | `showOnlySelected` 用写 `hidden` 实现（[store.ts:914-926](../src/store.ts#L914-L926)），用错会让流程图里也少东西 | 压暗用 class + CSS 变量，只改 `opacity`/`filter`，不碰 `data.hidden` |
| **力导向抖动/不稳定** | 同一张图每次切都换形状，人会失去空间记忆 | 固定种子 + 结构签名缓存；只有结构变化或点「重排」才重算 |
| **规模越界** | 300+ 节点时 React Flow 全量渲染会拖 | 超过 250 节点给一次提示（不阻塞），并把点半径与标签密度降级 |
| **e2e 回归面** | `run-e2e.sh` 是显式列表，新组要手动加；`settings` 新字段会进备份 | 备份断言里只比 `mdAuthor`（[e2e-12:71](../scripts/e2e-12-backup.mjs#L71)），低风险，但要跑一遍全量 |
| **无单测基建** | 仓库没有 vitest，纯函数（模型、布局）无法单测 | 布局函数写成纯函数，靠 e2e 断言最终坐标；若后续要长期维护，再引入最小测试器（不在本期） |

## 9. 验收标准（e2e-21 断言草案）

1. 顶栏分段控件可切换；切到图谱后画布出现、流程图卸载。
2. 节点数 = 非分组 / 非隐藏 / 有连线的纯文本节点之外的数量；分组框不在其中。
3. 焦点节点坐标落在视口中心 ±40px。
4. 1 跳邻居数量正确；切到 2 跳后节点集合严格变大；点空白后恢复全亮。
5. 双击某点 → 回到流程图、该节点 `selected`、视口对准它。
6. 虚线边在图谱中仍是 `stroke-dasharray`；不合规标签的边带 ⚠ 标记。
7. **切走再切回，流程图里所有节点的 `position` 与切换前逐字节一致**（D3 的守门断言）。
8. 刷新后仍停留在图谱（settings 记忆），但 localStorage 里的 doc **没有** `viewMode` 字段（D5 的守门断言）。
9. 隐藏某节点后切图谱：该点不出现；切回流程图它仍是隐藏状态（D13 的守门断言）。
10. 120 点 / 250 边夹具下，图谱首屏渲染 < 800ms（宽松阈值，仅防退化）。

## 10. 明确不做

- **ER 图导入**：`erDiagram` 现在会被当成一个叫 `erDiagram` 的节点，关系行整行丢弃、0 条边（[mermaid.ts:533](../src/lib/mermaid.ts#L533)、[mermaid.ts:398](../src/lib/mermaid.ts#L398)）。要支持就是另一个上游功能（解析器、基数、往返导出）。
- **依赖方向建模**：给 `关联` 加"引用方向 + 1:N"要动十条类型规范、检查器、导出与测试，属于模型改动，不是视图改动。
- **图谱内编辑**（连线、删除、改标签）：只读是本期边界。
- **字段级子图**：把字段画成节点会立刻爆炸到 10 倍节点数，且字段名来自一段自由文本（`values.columns`），启发式不可靠。
- **环检测 / 度数统计**：`关联` 成环不必然是错，先不引入"环"这个新概念。
- **图谱导出**（SVG/PNG）：现有导出是 mermaid 与工程文件，加图形导出要走 pele 渲染链，另算。
- **同组折叠成一个点**：会藏信息，等真到 120 节点再看。

## 12. 三个残留小项（需要你点头）

1. **剧本面板**：图谱模式下 `TimelinePanel` 建议收起（点节点不渲染字段，回放看不到效果），播放状态不重置。→ 推荐收起。
2. **边标签**：默认不常显，悬停显示 `类型: 说明`。→ 推荐如此（120 条常显标签必糊）。
3. **D7 的读法**：本方案是"照你画的方向画箭头"。若你的意思是"表与表之间应当有引用方向（谁引用谁）"，那要走到 §10 的"依赖方向建模"，本评估只覆盖前者。
