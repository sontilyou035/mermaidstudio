# 关系图谱：可行性评估与实施方案

> 结论先说：**值得做，但要收窄成"只读·焦点邻域"这一件事**。增量约 850 行产品代码 + 一组 e2e，3 天量级。最大的成本不是力导向，而是"第二套交互模型"——这一点已经被"复用 React Flow"消掉了。

## 1. 已经拍定的决策

| # | 决策 | 取值 |
| --- | --- | --- |
| D1 | 主任务 | **从焦点节点看依赖邻域**；全局总览靠"缩小视角"顺带得到；不做汇报呈现 |
| D2 | 可编辑性 | **只读**。点选同步检查器，双击回流程图定位，不能改结构 |
| D3 | 坐标归属 | 布局坐标**只活在组件里**，绝不写回 `doc.nodes[].position` |
| D4 | 视觉过滤归属 | 聚焦压暗是纯视觉，**不得借用 `hidden`**（`hidden` 会进图层和文档） |
| D5 | 开关位置 | 顶栏分段控件；模式记在全局 `settings`，**不进 `.mermaid.json`** |
| D6 | 规模 | 按 ≤120 节点 / ≤250 边设计与验收 |
| D7 | 方向 | 连线按作者画的方向画箭头（`data.endMarker`，默认 `arrow`），**不推断外键方向** |
| D8 | 节点画法 | Obsidian 式：一个圆点 + 下面的名字。**圆点面积与连线数成正比**（直径随 √条数 增长）；焦点不额外放大、不加光环、标签不垫底色 |
| D9 | 布局 | 手写力导向：焦点钉在圆心、BFS 跳数一圈圈往外 + 收敛后一次性渲染，零新依赖。**换焦点延迟 280ms 再重排**（保住双击，见 §5） |
| D10 | 载体 | 复用 React Flow：新增 `dot` 节点类型 + `graph` 连线类型 |
| D11 | 聚焦操作 | **打开时全部正常显示、没有焦点**；单击才聚焦（1 跳正常、其余半透明）+ 跳数档位 1/2/全部 + 点空白还原 |
| D12 | 诊断语义 | 继承既有图语言：虚线 = 待确认项（可筛"只看待确认"）、不合规标签连线标 ⚠ |
| D13 | 分组与可见性 | 不画分组框，同 `groupId` 同底色；`hidden` 一致不画；纯文本节点默认不画 |
| D14 | 命名 | 视图 =「关系图谱」，聚焦态 =「焦点邻域」，距离 =「跳」 |

## 2. 为什么不是"把 dagre 换成力导向"

现成的 `autoLayout` 就是 dagre（[layout.ts:111](../src/lib/layout.ts#L111)），它的输出是**分层有向图**——所有节点同等显眼，看不出"我离这张表有多远"。

真正让人发现问题的不是布局算法，而是**压暗**：焦点之外压暗到四成左右后，1 跳邻居自己浮出来，2 跳再补上一圈。这件事 dagre 表达不了，力导向本身也不表达；力导向只负责让**同一圈的邻居按亲疏自己抱团**，而不是按 dagre 的格子排队。所以力导向是"手感"，压暗才是"功能"。评估时别把预算花错地方。

## 3. 方案对比

| 方案 | 手感 | 成本 | 风险 | 结论 |
| --- | --- | --- | --- | --- |
| **A. React Flow + 手写力导向** | Obsidian 同级 | 中 | 需要两个新节点/边类型 | **选它** |
| B. 自建 SVG 画布 | 可控但需打磨 | 中高 | 平移/缩放/命中/选中/主题全部重写（约 200 行易错代码），且与画布的交互手感会分叉 | 否 |
| C. 引入 `d3-force` | 最好 | 低 | 多一个运行时依赖；本仓库"能自己写就不加" | 备选 |
| D. 纯 BFS 同心环（不跑力） | 确定性最好 | 低 | 跨环连线挤成一圈，看不出簇 | 否 |

选 A 的决定性理由：`getRfInstance().fitView` 被顶栏「适应视图」和左栏拖入定位依赖（[rf.ts](../src/lib/rf.ts)、[Toolbar.tsx:81](../src/components/Toolbar.tsx#L81)、[Palette.tsx:40](../src/components/Palette.tsx#L40)）。复用 React Flow，这两个功能在图谱模式下**零改动**继续工作；自建画布则要维护两套视口语义。

C 与 A 不冲突：真跑起来手感不够，再把 100 行手写模拟换成 `d3-force`，接口不变。这是一个可以**事后低成本升级**的决定，所以现在不抢先加依赖。

## 4. 数据从哪来（派生模型，不改文档）

输入只有 `doc.nodes` / `doc.edges`，派生规则：

- **排除** `data.isSubgraph` 的节点（分组框是流程图的排版概念）；
- **排除** `hidden` 的节点与边（与图层开关一致）；
- **纯文本节点**（`shape === 'text'`，是注释不是实体）默认不画，除非它有连线；
- **保留** `groupId` 作为同色线索，不画框；
- **边不聚合**：同一对表之间的多条连线全部保留（它们通常是不同字段的关系，合并会丢信息）。

派生结果是一个纯函数输出，不写回文档：

```ts
interface GraphModel {
  nodes: { id, label, fieldCount, columns, groupIndex }[]  // groupIndex: -1 = 不属于分组
  edges: { id, source, target, dashed, warn, arrow, label }[]
  neighbors: Map<nodeId, nodeId[]>   // 无向邻接表
}
bfsHops(model, fromId) → Map<nodeId, number>   // 最短跳数，视图按需调用
```

`dashed` 直接读 `data.lineStyle === 'dashed'`（既有约定：虚线 = 待确认项，见 [exporters.ts:56](../src/lib/exporters.ts#L56)）；`warn` 用现成的 `isEdgeLabelConforming()`（[edgeLabels.ts:87](../src/lib/edgeLabels.ts#L87)）。

## 5. 布局：可复现的手写力导向

1. **初值**：焦点当根（没有焦点时取度数最高的表），从根 BFS，跳数即环序，角度按**黄金角**散布（每圈再整体转一个黄金角），固定随机种子做微小抖动。**不能按槽位均分**：均分会让两个邻居永远正对面，小图就被摆成一条直线。
2. **力**：连边弹簧（目标长度按环差）+ 斥力（O(n²)，120 节点每 tick 7,200 对，可忽略）+ 最小间距碰撞 + **环约束**（把节点拉回它那一跳的半径）+ **回槽力**（很弱，只把节点拴在它的扇区里，否则只有两个邻居时斥力会把它们顶成正对面，又变回一条直线）。
3. **根（焦点）pin 在原点**，其余节点按跳数分布在不同半径上；视图再把原点摆到视口中心，就是"圆心聚焦"。
4. **收敛后一次性渲染**（320 tick，< 50ms），不做逐帧动画——否则每帧一次 React 重渲染，手感没赚到先亏性能。
5. **「重排」按钮**：换一个种子重新播种 + 重跑，用于打散意外重叠。
6. **缓存**：以"结构签名"（节点 id 列表 + 边端点列表）为缓存键。在流程图里拖动节点只改 `position`，不会让图谱重新洗牌；增删连线才重算。
7. **手动摆放**：在图谱里拖动过的点会把坐标记进视图状态（`overrides`），重排时优先使用；它们不写回文档，点「重排」清空。焦点节点被钉到原点时，才让出它自己的手动位置——而且是在重排真正发生的那一刻才让出，否则节点会在单击与双击之间跳走。

**为什么换焦点要延迟 280ms。** 立即重排的话，单击的瞬间节点就挪到光标外，真实的第二次点击永远打不中——这是第一版翻车的地方（当时干脆去掉了重排）。既然现在要"焦点在圆心"，就只能延迟：单击后先立即压暗，280ms 后再重排 + 把原点摆到视口中心；这 280ms 内收到第二下 click（`detail=2`）就当作双击，撤销这次重排并回到流程图。`FOCUS_DELAY_MS` 在 [GraphView.tsx](../src/components/GraphView.tsx) 里。

> 环约束是第二个必需项：只有弹簧和斥力时，2 跳的节点会被拉回 1 跳附近，"越远越远"的视觉承诺就没了（单测 `跳数决定离根多远` 就是这么红掉的）。

为什么同步跑到位而不是动画：Obsidian 的动画是为了"探索感"，我们的场景是"看一眼依赖"。同步计算同时换来**可断言性**——e2e 能直接读最终坐标，而不是等动画结束。

## 6. 交互

| 操作 | 行为 |
| --- | --- |
| 打开图谱 | 全部正常显示：没有焦点、没有压暗（布局仍以度数最高的表为圆心） |
| 单击节点 | 设为焦点：1 跳正常、其余半透明（节点与连线一起），**280ms 后焦点移到圆心**；写 `selectOnly([id])` 让检查器跟上 |
| 跳数 1 / 2 / 全部 | 键盘 `1` / `2` / `0` + 画布角落小控件；改变高亮范围 |
| 点击空白 / `Esc` | 取消焦点与选中，回到"整张图装进视口" |
| 双击节点 | 撤销待执行的重排，切回流程图 + `selectOnly([id], true)` 定位该表 |
| 悬停节点 | 圆点变绿（不放大——大小已经用来编码连线数了） |
| 悬停边 | 原生 tooltip 显示 `类型: 说明`（`<title>`，顺便可被读屏软件读到） |
| 拖动节点 | 手动摆放这个点：只改视图坐标，不写文档、不进撤销栈；点「重排」清掉 |
| 滚轮 / 拖拽空白 | 缩放 / 平移（React Flow 原生）；空格 + 拖动同样平移 |

视觉口径（对齐 Obsidian）：连线 1px、颜色 `rgb(100, 116, 139)`；箭头 8px；圆点直径 `8 + √度数 × 3.4`（上限 22px），所以连接越多面积越大；焦点只把名字加粗、提到最上层，不改变圆点本身；悬停把圆点变绿，同样不改大小。小图会自动放大填满画布（上限 1.5×），大图按包围盒缩到装得下。

只读的边界很清楚：图上任何操作都不调用 `commit()`，因此不进撤销栈、不标 dirty。`selectOnly` / `selectEdge` 走的是裸 `set()`（[store.ts:843-873](../src/store.ts#L843-L873)），本来就不碰历史，正好可用。

## 8. 风险清单

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| **RF 单实例假设** | `getRfInstance()` 只存一个实例；两个画布同时挂载会互相抢 | `App` 里条件渲染，卸载流程图后再挂图谱；图谱也在 `onInit` 里 `setRfInstance` |
| **坐标被动写回** | React Flow 的 `onNodesChange` 在流程图里会把位置写进 doc 并标 dirty（[store.ts:413-432](../src/store.ts#L413-L432)） | 图谱的 `onNodesChange` **只写组件内的 `overrides`**，从不触碰 `doc`；e2e 有"拖动节点不写回文档坐标"的守门断言 |
| **`selected` 随文档落盘** | 选中是文档数据，点一次就会在下次保存时写盘（既有行为） | 接受（不标 dirty、不进历史）；图谱不得调用 `commit()` |
| **聚焦误用 `hidden`** | `showOnlySelected` 用写 `hidden` 实现（[store.ts:914-926](../src/store.ts#L914-L926)），用错会让流程图里也少东西 | 压暗用 class + CSS 变量，只改 `opacity`/`filter`，不碰 `data.hidden` |
| **力导向抖动/不稳定** | 同一张图每次切都换形状，人会失去空间记忆 | 固定种子 + 结构签名缓存；只有结构变化或点「重排」才重算 |
| **规模越界** | 300+ 节点时 React Flow 全量渲染会拖 | 超过 250 节点给一次提示（不阻塞）；**不做自动降级**——静默改变视觉比慢一点更糟 |
| **e2e 回归面** | `run-e2e.sh` 是显式列表，新组要手动加；`settings` 新字段会进备份 | 备份断言里只比 `mdAuthor`（[e2e-12:71](../scripts/e2e-12-backup.mjs#L71)），低风险，但要跑一遍全量 |
| **无单测基建** | 仓库原本没有测试运行器 | 用 Node 内置 `node:test` + 类型剥离，`scripts/unit-graph.mjs` 覆盖模型与布局；不引 vitest |
| **聚焦一改布局就毁双击**（实现中真实发生） | 单击后节点跑到光标外，第二次点击落空 | 换焦点延迟 280ms 重排；双击的第二下 click 撤销这次重排 |
| **RF 的自定义 `onDoubleClick` 不触发**（实现中真实发生） | 合成事件与 CDP 双击都没走到 `onNodeDoubleClick`（DOM 上确实挂了 handler，直接调用 props 却生效） | 改用 click 的 `detail >= 2` 判定双击（真实双击的第二下 click 一定带 detail=2），两条路都保留 |

## 9. 验收标准（`scripts/e2e-21-graph.mjs`，25 条全绿）

1. 顶栏分段控件可切换；切到图谱后画布出现、**流程图卸载**（同一时刻只有一个 `.react-flow`）。
2. 视图模式写进 `settings`。
3. 只画实体表：数量正确。
4. **刚切进来全部正常显示**：没有焦点、没有压暗（节点和连线都没有）。
5. 分组框 / 隐藏表 / 无连线的注释节点都不进图。
6. **连线是 1px 细线**，颜色 `rgb(100, 116, 139)`。
7. **圆点面积随连线数增长**，焦点不额外放大。
8. 焦点没有渐变光环、标签没有白色底。
9. **拖动节点只移动这个点**：画布不平移、焦点不变。
10. **拖动节点不写回文档坐标**。
11. 虚线 = 待确认项、不合规标签标 ⚠、方向画箭头（三条同时验）。
12. 单击聚焦：1 个 `is-focus`，2 跳以外压暗，1 跳仍亮。
13. 聚焦同步检查器选中（`doc.nodes[].selected`）。
14. **焦点被摆到圆心（±80px），名字在圆点下面。**
15. 切到 2 跳：压暗的变少、亮的变多。
16. 点空白清掉聚焦。
17. 双击回到流程图。
18. 回到流程图后选中那张表（`selectOnly(..., true)` 的 fitView 负责对准，e2e 只断言选中）。
19. **切走再切回，所有节点 `position` 与切换前逐字节一致**（D3 的守门断言）。
20. **隐藏状态没有被图谱改写**（D13 的守门断言）。
21. 视图模式记在全局 `settings`。
22. **工程文档里没有 `viewMode` 字段**（D5 的守门断言）。
23. 刷新后仍停在关系图谱。
24. 全程 0 控制台错误、0 未捕获异常（控制台错误现在也会让脚本以 1 退出）。

另外 `npm run test:unit`（`scripts/unit-graph.mjs`，11 组）守纯函数：可见性过滤、表名回落、无向邻接与最短跳数、诊断标记与箭头、同组同色、布局确定性与焦点居中、跳数决定半径、两种「不能排成一条直线」（两个邻居 / 1 跳与 2 跳）、结构签名。

> 原草案里的"焦点落在视口中心 ±40px"已经落地（第 14 条）；"120 点夹具首屏 < 800ms"还没做——等真实大图出现再补，避免用一个人造夹具把阈值钉死。

## 10. 明确不做

- **ER 图导入**：`erDiagram` 现在会被当成一个叫 `erDiagram` 的节点，关系行整行丢弃、0 条边（[mermaid.ts:533](../src/lib/mermaid.ts#L533)、[mermaid.ts:398](../src/lib/mermaid.ts#L398)）。要支持就是另一个上游功能（解析器、基数、往返导出）。
- **依赖方向建模**：给 `关联` 加"引用方向 + 1:N"要动十条类型规范、检查器、导出与测试，属于模型改动，不是视图改动。
- **图谱内编辑**（连线、删除、改标签）：只读是本期边界。
- **字段级子图**：把字段画成节点会立刻爆炸到 10 倍节点数，且字段名来自一段自由文本（`values.columns`），启发式不可靠。
- **环检测 / 度数统计**：`关联` 成环不必然是错，先不引入"环"这个新概念。
- **图谱导出**（SVG/PNG）：现有导出是 mermaid 与工程文件，加图形导出要走 pele 渲染链，另算。
- **同组折叠成一个点**：会藏信息，等真到 120 节点再看。

## 14. 实现记录（与计划的偏差）

实现后回看，十七处与评估时的计划不同或踩了坑，原因都在下面：

1. **焦点居中走了个来回**：第一版每次单击都重排，节点在两次点击之间跑掉、双击永远打不中，于是干脆去掉了重排；第二轮要求"圆心聚焦"后，改成**延迟 280ms 重排 + 双击撤销**，两个行为都保住了（§5）。
2. **展开卡片整条功能被移除了**（用户反馈「加号是多余功能」）。第一版曾用 25 行的只读卡片替代 `BlockNode`（它是编辑器组件，挂进只读视图等于把编辑入口偷渡进来）；现在连卡片一起删掉：图谱只负责看关系，字段请回检查器。
3. **双击用 click 的 `detail >= 2` 判定**。RF 的自定义 `onNodeDoubleClick` 在这次实现里没有触发（DOM 上确认有 handler，直接调用 props 生效，事件却到不了），改用 detail 判定后真实双击与 e2e 都稳定。
4. **补了 Node 内置单测**（`scripts/unit-graph.mjs`）。原计划"无单测基建，靠 e2e 间接验证"——实际发现力导向的正确性（确定性、环序）用浏览器断言太钝，而 Node 22 能直接跑 `.ts`，不需要引入 vitest。

5. **力参数的单位踩了两个坑**，都是靠单测才暴露的：
   - 重力写成 `xs[i] * k * 0.012`（乘了间距基数），实际每像素 2.28 的力度把整张图钉死在固定半径上——表现是"改碰撞半径几乎没效果"，而参数看起来改对了。重力必须与 `k` 无关。
   - 环半径必须**吃掉节点尺寸**：早期卡片按 130 半径占位、进碰撞与环半径累加，否则卡片会压在邻居身上（卡片移除后回到统一半径）。
6. **压暗的初始取值太低**：先写成 15%，截图一看等于"消失"；最终定 30%（更接近 Obsidian 那种"退到背景里"的感觉，但邻居仍然清晰）。这也是为什么要在实现阶段拍真实截图，而不是只看断言。

7. **节点只有圆点和名字**：没有徽标、没有展开卡片、没有 `＋`。加号在只读视图里是纯噪音，看字段回检查器更合适。
8. **图谱模式下顶栏把「自动布局」和布局方向藏起来**，只留「适应视图」：这两个动作只作用于 dagre 画布，在图谱里放着会让人以为能重排图谱。

9. **小图被排成一条直线**：环上按槽位均分角度，两个邻居永远正对面；而且每圈的第 0 个节点都在 0°，链式图的 1 跳和 2 跳也共线。改成黄金角散布 + 每圈再整体转一个黄金角 + 很弱的「回槽力」，否则斥力又会把两个邻居顶成正对面。
10. **连线停在离圆心半个节点宽的地方**：连接点原本锚在节点框的边界上。改成把两个 `Handle` 都钉在圆点圆心，边线由 `GraphEdgeView` 按两端圆点半径各缩回一点（半径 + 1.5px），正好贴在自己那个圆点的边缘上。
11. **长表名被截断**：节点框固定 140 宽，长表名（`ty_product.mt_store_sku_wide`）会被省略号吃掉。标签改为绝对定位、允许溢出节点框（最大 230px）。
12. **焦点标签的底色反而糊住了圆点**：上一版给焦点标签垫了 `--bg` 底色，叠在圆点/连线上像一块白斑；按要求去掉，焦点只用「名字加粗 + 提到最上层」区分。
13. **节点大小改成编码信息**：原来只按焦点与否放大；现在圆点面积随连线数增长（半径 √度数），与 Obsidian 一致，焦点不再额外放大。
14. **刚进来不再自动聚焦**：自动聚焦会把 1 跳以外的表压暗，看起来像"一进来就有东西丢了"。改成进来全部正常，点一下才进入 1 跳视图。
15. **悬停从"放大"改成"变绿"**：放大和"大小=连线数"的编码打架，绿点只做悬停反馈，不参与信息编码。
16. **居中不能靠 `fitView` 之后再 `setCenter`**：`fitView` 是带动画的，`fitView()` 返回的 promise 不等动画结束，后到的 `setCenter` 会被它的动画覆盖——表现就是"怎么调都稳定偏一截"。改成自己按节点包围盒算缩放，再 `setCenter`。
17. **React Flow 的 `position` 是节点框的左上角，而布局算的是"圆点中心"**：不换算的话，焦点会稳定偏半个节点宽。现在统一走 `toNodePosition` / `toAnchor` 两个换算，节点框固定 `140×70`，圆点锚在顶部正中，大小变化时圆心不动。
