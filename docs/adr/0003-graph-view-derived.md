# 关系图谱是只读派生视图（坐标与过滤都不进文档）

**Status**: accepted — 2026-11-13

主视图新增的「关系图谱」由 `doc.nodes` / `doc.edges` 派生：力导向算出的坐标只活在组件里，绝不写回 `node.position`；聚焦时的压暗和"只看待确认"筛选是纯视觉，绝不借用 `hidden`；视图模式记在全局 `settings`，不进 `.mermaid.json`。图谱里任何操作都不调 `commit()`，因此不进撤销栈、不标 dirty。

理由是三条边界相互加固：`position` 是用户手工排过的资产（还牵着 subgraph 盒子和 `syncGroups` 的贴合逻辑），力导向一写回就等于"每次切视图自动毁掉排版"；`hidden` 已经是图层语义，借它做聚焦会让流程图里也少东西；视图模式是"看的方式"不是"图的内容"，塞进工程文件会让导入/导出/往返测试多背一个与 Mermaid 无关的字段。

## Considered Options

- **写回坐标，两个视图共用一套位置**：切回流程图会被打散，且与自动布局/编组互相踩。
- **用 `hidden` 实现聚焦**：实现最省事，但会污染文档与图层，切回流程图后隐藏状态还在。
- **把视图模式存进 `DiagramDoc`**：跟着图走、可分享，但工程文件格式要为纯 UI 状态背字段。
- **自建 SVG 画布**：控制力最大，但平移/缩放/命中/选中/主题要重写一遍，且 `getRfInstance().fitView`（顶栏「适应视图」、左栏拖入定位）会分叉成两套视口语义。

## Consequences

- 图谱的坐标、展开状态、跳数档位都是易失的；刷新后回到全图，需要重新聚焦。这是刻意的：空间记忆让位于"文档不被视图污染"。
- 布局必须可复现（固定种子 + 按结构签名缓存），否则每次切换都换形状，人会失去判断依据。
- 图谱模式下判据是"点节点不渲染字段"，剧本回放看不见效果，因此剧本面板在该模式下收起。
- 后续若要让图谱可编辑，等于引入第二个编辑器：连线端口、标签规范、拐点、`&` 展开都要重做。那是一条独立的路，不在本决定范围。
- 若"谁引用谁"成为刚需，需要在模型层给 `关联` 补方向与基数，并改十条类型规范、检查器与导出；视图层不动。
